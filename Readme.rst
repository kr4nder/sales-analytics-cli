Тестовое задание для C# разработчика
====================================

Цель задания
------------
Оценить навыки кандидата в работе с ключевыми технологиями экосистемы .NET:  
– работа с файловой системой и сериализация (CSV, JSON)  
– асинхронное программирование (`async`/`await`)  
– LINQ и обработка коллекций  
– многопоточность (`Parallel`, `Task`)  
– внедрение зависимостей (DI)  
– написание юнит-тестов (xUnit, Moq)  

Необходимо разработать консольное приложение (CLI) на **.NET 10**, которое принимает аргументы командной строки для выбора режима работы и входных/выходных файлов.

Описание предметной области
---------------------------
Приложение обрабатывает данные из файла **sales_5000.csv** о продажах в формате CSV со следующей структурой:

========= =========== ============  ================= ================= =========== ========= =============== ==============  ================  =======
order_id, order_date, customer_id,  product_category, region, quantity, unit_price, discount, payment_method, delivery_days,  customer_rating,  revenue
========= =========== ============  ================= ================= =========== ========= =============== ==============  ================  =======
10001,    1/1/2022,   1102,         Beauty,           South,  7,        373.65,     0.28,     Wallet,         10,             4.7,              1883.2
10002,    1/2/2022,   1435,         Clothing,         South,  7,        47.74,      0.09,     Card,           6,              3.9,              304.1
10003,    1/3/2022,   1860,         Beauty,           East,   3,        311.28,     0.31,     COD,            6,              2.5,              644.35
10004,    1/4/2022,   1270,         Electronics,      West,   5,        524.47,     0.02,     Wallet,         6,              1.6,              2569.9
10005,    1/5/2022,   1106,         Clothing,         West,   5,        139.87,     0.33,     Wallet,         4,              4.9,              468.56
========= =========== ============  ================= ================= =========== ========= =============== ==============  ================  =======

Файл может содержать тысячи записей. Приложение должно уметь:
- Читать CSV, преобразовывать строки в объекты `Sale`.
- Выполнять аналитические операции:
  1. Общая сумма продаж по категориям.
  2. Топ-4 категорий товаров по общему количеству проданных единиц.
  3. Средняя цена за каждый месяц (группировка по месяцу).
  4. Топ-5 покупателей по рейтингу.
  5. Среднее время доставки.
  6. Средняя скидка, по категории (группировка по месяцу).
- Выводить результаты либо в консоль (в читаемом виде), либо сохранять в JSON-файл.
- Обрабатывать ошибки (отсутствие файла, неверный формат, пустой файл).

Режимы работы (аргументы командной строки)
------------------------------------------

Приложение должно поддерживать следующие **режимы**, которые задаются через аргумент `--mode` (или `-m`):

========== ==================================================================================================================================================
Режим      Описание
========== ==================================================================================================================================================
`console`  Синхронное чтение CSV, вычисление трёх аналитик, вывод в консоль.
`file`     То же самое, но результаты сохраняются в JSON-файл (путь задаётся `--output`).
`async`    Асинхронное чтение файла (через `StreamReader` с `ReadLineAsync`) и асинхронная запись JSON. Все операции ввода-вывода должны быть неблокирующими.
`parallel` Параллельная обработка записей при вычислении аналитик (использовать `Parallel.ForEach` или `PLINQ`).
`di`       Использовать DI-контейнер для регистрации всех сервисов (чтение, парсинг, вычисления, запись). Запуск через `HostBuilder` или `ServiceCollection`.
`full`     Комбинированный режим: асинхронный ввод-вывод + параллельные вычисления + DI.
========== ==================================================================================================================================================

Дополнительные аргументы:
-------------------------
- `--input` (обязательный) – путь к входному CSV-файлу.
- `--output` (опционально) – путь для сохранения результатов (для режимов `file` и `full`).
- `--help` – вывод справки по доступным режимам.
- `--start_date` - дата с которой учитывать статистику.
- `--end_date` - дата до которой учитывать статистику, не увключительно.

Примеры запуска:
```bash
dotnet run --mode=console --input=sales_5000.csv
dotnet run --mode=file --input=sales_5000.csv --output=result.json
dotnet run --mode=async --input=sales_5000.csv
dotnet run --mode=full --input=sales_5000.csv --output=result.json
```

Технические требования
======================

1. Архитектура
--------------
- Разделение на слои:  
  - **Модели** (`Sale`)  
  - **Сервисы** для чтения/парсинга (`ICsvReader`, `ISaleParser`), вычислений (`IAnalyticsService`), записи (`IResultWriter`).  
- Все сервисы должны быть зарегистрированы в DI-контейнере (для режимов `di` и `full`). Для остальных режимов DI не обязателен, но приветствуется.

2. Работа с файлами
-------------------
- Чтение CSV с помощью `StreamReader` и построчный парсинг.  
- Парсинг должен корректно обрабатывать заголовки, пустые строки, культуры (разделитель `;` или `,` – на усмотрение, но указать в документации).  
- Запись JSON с использованием `System.Text.Json` или `Newtonsoft.Json`. Результат должен содержать три аналитических блока.

3. LINQ
-------
- Для вычислений обязательно использовать LINQ-запросы (`GroupBy`, `OrderBy`, `Sum`, `Average`, `Take`).

4. Асинхронность
----------------
- В режиме `async` все методы ввода-вывода (чтение файла, запись результата) должны быть асинхронными.  
- Вычисления могут выполняться синхронно, но вызовы должны быть обёрнуты в асинхронный метод.

5. Многопоточность
------------------
- В режиме `parallel` хотя бы одна из аналитик (например, вычисление суммы по категориям) должна использовать `Parallel.ForEach` или `AsParallel()`.  
- Обратить внимание на потокобезопасность при агрегации (использовать `Interlocked` или `ConcurrentDictionary`).

6. DI
-----
- В режиме `di` приложение должно быть построено на `Microsoft.Extensions.DependencyInjection`.  
- Использовать `IHost` или просто `ServiceProvider`.  
- Регистрация сервисов с соответствующими временами жизни (Transient, Scoped, Singleton – обосновать выбор).

7. Обработка ошибок
-------------------
- Приложение не должно падать на некорректных данных – выводить осмысленное сообщение и завершаться с кодом возврата `1`.  
- Проверять наличие файла, доступность директории для записи.

Требования к юнит-тестам
------------------------
- Использовать **xUnit** и **Moq**.  
- Покрыть тестами:
  - Парсинг CSV-строк в объекты `Sale` (граничные случаи: пустая строка, неверный формат даты).  
  - Логику вычислений (каждая аналитика проверяется на небольшом наборе данных).  
  - Асинхронные методы (проверить, что они действительно асинхронны, можно через `Task.FromResult` и моки).  
  - Проверку корректности работы DI (регистрация и разрешение зависимостей).  
- Тесты должны быть изолированы (не использовать реальные файлы – применять `StringReader`/`StringWriter` или моки).

Критерии оценки
---------------
1. **Читаемость и структура кода** – соблюдение принципов SOLID, нейминг, комментарии (где нужно).  
2. **Корректность работы** – все режимы выполняют заявленные функции без ошибок.  
3. **Эффективность** – разумное использование асинхронности и параллелизма.  
4. **Тестирование** – полнота покрытия, качество тестов (использование моков, проверка исключений).  
5. **Работа с DI** – правильная регистрация, использование абстракций.  
6. **Обработка ошибок** – понятные сообщения для пользователя.  
7. **Документация** – наличие `README.md` с инструкцией по сборке, запуску и описанием аргументов.
