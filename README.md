# Аналитика продаж — консольное приложение на .NET 10

CLI-приложение, которое читает CSV-файл с продажами, считает шесть аналитических
показателей и выводит результат в консоль или сохраняет в JSON.

Решение выполнено по техническому заданию из [`Readme.rst`](Readme.rst) и демонстрирует
работу с файловой системой и сериализацией, LINQ, `async`/`await`, многопоточность,
внедрение зависимостей и юнит-тестирование.

## Быстрый старт

Требуется только **.NET SDK 10.0** — сторонних установок и настроек не нужно.

```bash
# сборка
dotnet build

# запуск всех тестов
dotnet test

# расчёт с выводом в консоль
dotnet run --project src/SalesAnalytics.Cli -- --mode=console --input=sales_5000.csv

# расчёт с сохранением результата в JSON
dotnet run --project src/SalesAnalytics.Cli -- --mode=file --input=sales_5000.csv --output=result.json
```

Собранный исполняемый файл можно вызывать напрямую:

```bash
SalesAnalytics.Cli --mode=full --input=sales_5000.csv --output=result.json
```

> Двойное тире `--` в команде `dotnet run` отделяет аргументы приложения от аргументов SDK.

## Аргументы командной строки

| Аргумент | Псевдоним | Обязательный | Описание |
| --- | --- | --- | --- |
| `--mode` | `-m` | нет | Режим работы. По умолчанию `console`. |
| `--input` | `-i` | **да** | Путь к входному CSV-файлу. |
| `--output` | `-o` | для `file` | Путь к JSON-файлу результата. Без него отчёт печатается в консоль. |
| `--start_date` | — | нет | Дата, с которой учитывать записи, **включительно**. |
| `--end_date` | — | нет | Дата, до которой учитывать записи, **не включая**. |
| `--max-rows` | — | нет | Максимум строк в блоке консольного отчёта. `0` — без ограничения. По умолчанию `24`. |
| `--help` | `-h` | нет | Справка по параметрам. |

Значение можно передавать как через знак равенства, так и следующим аргументом —
`--mode=async` и `--mode async` эквивалентны. Имена `--start_date` и `--start-date`
принимаются оба.

Даты в аргументах разбираются в форматах `yyyy-MM-dd`, `dd.MM.yyyy`, `d.M.yyyy`,
`M/d/yyyy` и `MM/dd/yyyy`.

### Примеры

```bash
# все шесть аналитик по всему файлу в консоль
SalesAnalytics.Cli --mode=console --input=sales_5000.csv

# результат в файл
SalesAnalytics.Cli --mode=file --input=sales_5000.csv --output=result.json

# асинхронный ввод-вывод
SalesAnalytics.Cli --mode=async --input=sales_5000.csv

# асинхронный ввод-вывод + параллельный расчёт + DI
SalesAnalytics.Cli --mode=full --input=sales_5000.csv --output=result.json

# только 2022 год, короткими псевдонимами
SalesAnalytics.Cli -m parallel -i sales_5000.csv --start_date=2022-01-01 --end_date=2023-01-01

# полный консольный отчёт без усечения блоков
SalesAnalytics.Cli -m console -i sales_5000.csv --max-rows=0
```

## Режимы работы

| Режим | Ввод-вывод | Расчёт | Композиция зависимостей |
| --- | --- | --- | --- |
| `console` | синхронный | последовательный | вручную |
| `file` | синхронный | последовательный | вручную |
| `async` | асинхронный | последовательный | вручную |
| `parallel` | синхронный | параллельный | вручную |
| `di` | синхронный | последовательный | DI-контейнер |
| `full` | асинхронный | параллельный | DI-контейнер |

Режим влияет только на то, какие реализации подставляются в конвейер; сама
последовательность шагов «загрузить → посчитать → записать» во всех режимах одна и та же.

- **Асинхронный ввод-вывод** — файл открывается с флагом `FileOptions.Asynchronous`,
  строки читаются через `StreamReader.ReadLineAsync`, JSON пишется через
  `JsonSerializer.SerializeAsync`. Ни одна операция не блокирует поток.
- **Параллельный расчёт** — суммы по категориям считаются через `Parallel.ForEach`
  по диапазонам записей с локальным накопителем на поток и слиянием в
  `ConcurrentDictionary`; статистика доставки сводится через `Interlocked`;
  остальные блоки используют PLINQ.
- **DI** — сервисы регистрируются в `Microsoft.Extensions.DependencyInjection`
  и разрешаются из `IHost`.

## Формат входного файла

Ожидается CSV с заголовком и двенадцатью колонками:

```csv
order_id,order_date,customer_id,product_category,region,quantity,unit_price,discount,payment_method,delivery_days,customer_rating,revenue
10001,1/1/2022,1102,Beauty,South,7,373.65,0.28,Wallet,10,4.7,1883.2
```

| Колонка | Тип | Примечание |
| --- | --- | --- |
| `order_id` | целое | Идентификатор заказа. |
| `order_date` | дата | `M/d/yyyy`, `MM/dd/yyyy`, `yyyy-MM-dd`, `d.M.yyyy` или `dd.MM.yyyy`. |
| `customer_id` | целое | Идентификатор покупателя. |
| `product_category` | строка | Непустая. |
| `region` | строка | Непустая. |
| `quantity` | целое | Не отрицательное. |
| `unit_price` | число | Цена за единицу до скидки. |
| `discount` | число | Доля от 0 до 1: `0.28` — это 28 %. |
| `payment_method` | строка | Непустая. |
| `delivery_days` | целое | Не отрицательное. |
| `customer_rating` | число | От 0 до 5. |
| `revenue` | число | Выручка с учётом скидки. |

**Разделитель** определяется автоматически по строке заголовка: поддерживаются
запятая, точка с запятой и табуляция. Побеждает тот символ, который делит заголовок
ровно на 12 частей.

**Дробная часть** чисел отделяется точкой. Для файлов в европейском формате
(разделитель `;`) принимается и запятая: `373,65` будет прочитано корректно.

Пустые строки внутри файла пропускаются. Строка заголовка распознаётся автоматически
и не обязательна: файл без заголовка тоже читается.

## Аналитические показатели

1. **Общая сумма продаж по категориям** — сумма без скидки (`quantity × unit_price`),
   фактическая выручка (`revenue`) и количество заказов.
2. **Топ-4 категорий** по суммарному количеству проданных единиц.
3. **Средняя цена за единицу товара** по каждому календарному месяцу.
4. **Топ-5 покупателей** по средней оценке. При равных оценках выше тот, у кого больше заказов.
5. **Время доставки** — среднее, минимум и максимум в днях.
6. **Средняя скидка** по категории с разбивкой по месяцам.

Если заданы `--start_date` и `--end_date`, все показатели считаются по записям,
попадающим в полуинтервал `[start_date; end_date)`.

## Архитектура

```
src/
  SalesAnalytics.Core/            доменный слой, не зависит от способа запуска
    Models/                       Sale, AnalyticsReport, AnalyticsPeriod
    Abstractions/                 ISaleParser, ICsvReader, ISaleLoader,
                                  IAnalyticsService, IResultWriter, IResultWriterFactory
    Parsing/                      SaleParser, CsvReader, FileSaleLoader, CsvFormat
    Analytics/                    AnalyticsServiceBase, LinqAnalyticsService,
                                  ParallelAnalyticsService
    Output/                       ConsoleResultWriter, JsonResultWriter, ResultWriterFactory
    Application/                  AnalyticsPipeline
    DependencyInjection/          AddSalesAnalytics
    Exceptions/                   иерархия SalesAnalyticsException
  SalesAnalytics.Cli/             слой представления
    Configuration/                разбор аргументов, справка, ExecutionMode
    Composition/                  PipelineComposer
    Application.cs                сценарий запуска и коды возврата
    Program.cs                    точка входа
tests/
  SalesAnalytics.Tests/           xUnit + Moq
```

Ключевые решения:

- **`AnalyticsPipeline`** связывает три шага и ничего не знает ни о командной строке,
  ни о конкретных реализациях. Поведение режима определяется тем, что в него внедрено.
- **`AnalyticsServiceBase`** держит фильтрацию по периоду, метаданные и порядок блоков,
  а наследники переопределяют только способ расчёта. Поэтому последовательная и
  параллельная реализации гарантированно дают отчёт одинаковой структуры — это
  проверяется тестом на наборе из 5000 записей.
- **`ICsvReader` принимает `TextReader`, а не путь.** Разбор содержимого отделён от
  доступа к файлу (`ISaleLoader`), благодаря чему чтение тестируется через `StringReader`
  без создания файлов.
- **`IResultWriterFactory`** нужен потому, что цель записи известна только во время
  выполнения. Каталог результата проверяется до чтения файла и расчёта: бессмысленно
  тратить время на обработку, если сохранить отчёт всё равно некуда.

### Времена жизни сервисов

| Сервис | Время жизни | Обоснование |
| --- | --- | --- |
| `ISaleParser`, `ICsvReader`, `ISaleLoader`, `IAnalyticsService` | `Singleton` | Не хранят состояние между вызовами — состояние разбора живёт внутри вызова метода. Потокобезопасны, пересоздавать незачем. |
| `IResultWriterFactory` | `Singleton` | Хранит только ссылку на `TextWriter` и настройки; сами писатели создаются на каждый запуск. |
| `AnalyticsPipeline` | `Transient` | Объект-сценарий одного запуска. Дешёвый, а отдельный экземпляр снимает риск разделяемого состояния при параллельных запусках. |

## Обработка ошибок

Приложение не завершается аварийно на некорректных данных: все ожидаемые проблемы
наследуются от `SalesAnalyticsException`, превращаются в понятное сообщение в `stderr`
и дают код возврата `1`. Стек вызовов пользователю не показывается.

| Ситуация | Сообщение |
| --- | --- |
| Файл не найден | `Входной файл не найден: «nope.csv». Проверьте значение аргумента --input.` |
| Пустой файл | `Файл «empty.csv» не содержит данных о продажах: нет ни одной строки после заголовка.` |
| Битая строка | `Ошибка разбора CSV в строке 3: колонка «order_date» содержит «ЧТО-ТО», ожидалась дата в формате …` |
| Нет каталога для записи | `Каталог «C:\nope\dir» не существует. Создайте его или укажите другой путь в --output.` |
| Неизвестный режим | `Неизвестный режим «turbo». Доступные режимы: console, file, async, parallel, di, full.` |
| Пустая выборка по датам | `За период с 2030-01-01 по 2030-02-01 (не включая) не найдено ни одной записи.` |

| Код возврата | Значение |
| --- | --- |
| `0` | Отчёт успешно сформирован (в том числе вывод справки). |
| `1` | Неверные аргументы, недоступный файл или некорректные данные. |

## Тесты

```bash
dotnet test
```

162 теста на **xUnit** с моками **Moq**. Тесты изолированы: реальные файлы не
создаются и не читаются — используются `StringReader`, `StringWriter`, `MemoryStream`
и моки абстракций.

Что покрыто:

- **Разбор CSV** — валидная строка, пустая строка, неверный формат даты, неверное
  число колонок, нечисловые и выходящие за диапазон значения, выравнивание пробелами,
  разделитель `;` с запятой в дробной части, все поддерживаемые форматы дат.
- **Чтение файла** — пропуск заголовка и пустых строк, файл без заголовка, определение
  разделителя, номер физической строки в сообщении об ошибке, режим пропуска битых строк.
- **Асинхронность** — `TrackingTextReader` подтверждает, что `ReadAsync` выполняет
  только асинхронные чтения; строгие моки в тестах конвейера проверяют, что в
  асинхронном режиме вызываются `LoadAsync` / `AnalyzeAsync` / `WriteAsync`,
  а синхронные аналоги не вызываются ни разу.
- **Каждая из шести аналитик** — на малом наборе из задания, причём ожидаемые значения
  совпадают с приведённым в `Readme.rst` расчётом (`Beauty 3 549,39`,
  `средняя цена января 279,40`).
- **Эквивалентность реализаций** — параллельный расчёт сверяется с последовательным
  на 5000 записей, что проверяет корректность потокобезопасной агрегации.
- **Вывод** — состав блоков консольного отчёта, форматирование чисел, усечение строк,
  `snake_case` в JSON, обратная десериализация, отсутствие экранирования кириллицы.
- **DI** — разрешение всех абстракций, выбор реализации расчёта по режиму,
  объявленные времена жизни, состав композиционного корня для каждого режима.
- **Сценарий приложения** — справка, коды возврата, сообщения об ошибках.

## Принятые решения

Несколько мест техзадания допускали разное прочтение; ниже — что выбрано и почему.

**«Общая сумма продаж по категориям» считается без учёта скидки.** В примере
ожидаемого вывода сумма для Beauty равна `373,65 × 7 + 311,28 × 3 = 3 549,39`, то есть
`quantity × unit_price`. При этом в файле есть колонка `revenue` с выручкой уже за
вычетом скидки. Чтобы не терять ни одну из величин, отчёт содержит обе:
`gross_amount` соответствует примеру из задания, `net_revenue` — колонке `revenue`.

**Реализованы все шесть аналитик.** В описании режимов упоминается «вычисление трёх
аналитик», но перечислены шесть — считаются все шесть.

**Верхняя граница периода не включается.** Как и указано для `--end_date`:
`--start_date=2022-01-01 --end_date=2023-01-01` даёт ровно 2022 год.

**Консольный вывод усекается по умолчанию.** Блоки с разбивкой по месяцам дают
сотни строк. Усечение до 24 строк с явной пометкой сохраняет читаемость; полный
вывод доступен через `--max-rows=0` и всегда есть в JSON.

**Топ покупателей строится по средней оценке.** Покупатель встречается в файле
несколько раз, поэтому оценки усредняются; при равенстве средних выше оказывается
тот, у кого больше заказов.

**Режим по умолчанию — `console`.** Аргумент `--mode` можно не указывать;
обязателен только `--input`.
